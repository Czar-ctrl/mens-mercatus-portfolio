The Mercatus Blueprint Robot itself cannot run on the DreamHost shared host (CoreCLR SIGSEGV / runtime create failure), so it runs on the Mens Mercatus VPS and Assist reaches it through a same-origin proxy. The AI Studio app in the screenshots is the multimodal workspace (balance sheet, operational logs, compliance badges, NetzarLab, governance, NZC→NZG token rebalancing); figures in the guide are demo state inside that app.

1 · Architecture

Two pieces: a static portfolio on DreamHost shared hosting, and an ASP.NET Core 8 minimal API (the Blueprint Robot) on the VPS. The robot exposes three endpoints and loads its system prompt from its Blueprint Robot prompt file at boot.

  • GET /health
  • POST Blueprint API · chat
  • POST Blueprint API · assist

The AI Studio workspace (screenshots below) is a separate multimodal prototype — same Blueprint brief, different runtime.

2 · Gemini call shape

The robot uses an OpenAI-compatible chat/completions body (model + temperature + messages) so the provider is swappable via config (Llm:BaseUrl, Llm:Model, Llm:ApiKey — the key lives in server env, never in this page). Retries: up to 4 attempts on 429/502/503/504 or "UNAVAILABLE / high demand" bodies, exponential backoff ~0.6 s → 1.2 s → 2.4 s with jitter.

4 · Deploy note

  • Static site → DreamHost shared (files 644, dirs 755; additive uploads, never a wipe).
  • .NET robot → VPS as a systemd service behind nginx; DreamHost's grsec kernel kills CoreCLR, so it cannot run there.
  • Secrets stay in server env files; health reports llmConfigured as a boolean, never the key.
  • Rollback: restore the latest pre-deploy tarball on the shared host; restart the systemd unit on the VPS.
