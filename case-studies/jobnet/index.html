01 · Career pipeline

JobNet

A daily career pipeline that turns public job posts into a ranked shortlist and tailored drafts, and sends a letter only when the posting prints an employer address.

Human approval required

Open JobNet ApplicationAlternate JobNet entry

Challenge

Applying across many AI and engineering boards by hand is slow, and tools that submit on their own are unsafe. The job was to shorten the research and drafting loop without giving the system permission to apply or send mail.

Role and scope

Designed and operated the pipeline

  • Set a daily 20:00 SAST scrape, then a rank against the case studies. The previous run is mailed at 15:00 SAST.
  • Kept a human confirm step before any submit. The system queues work; it does not apply.
  • Added inbox watching so replies can be noticed, with notify paths that still require a person to send.
  • Published a live read-only shortlist so a reviewer can see the pipeline without touching a mailbox.

Architecture

  1. 01

    Collect

    Daily scrape at 20:00 SAST across public listings. Read-only collection.

  2. 02

    Match

    A hashed sentence embedding ranks each posting against JobNet, Assist, THINK, Forex, and SoundX, and keeps one role per company. The report names the closest case study and a line from the posting.

  3. 03

    Draft

    The 15:00 SAST report covers the previous run. A letter is prepared only for a role that clears the ranker.

  4. 04

    Send gate

    Mail leaves only if the address is on the posting, the domain resolves, and the letter names that title, company, and summary. Missing addresses are held, not guessed.

60–90 second demo

  1. Open the read-only shortlist. You should see roles, not a send button that fires mail.
  2. Open one queued draft and read the source it was written from.
  3. Look for the approval state. If the only next step is a human send, the gate is doing its job.
  4. Stop there. The 90-second demo is the boundary, not a live application.

AI behavior

  • AI-assisted: classification and a tailored draft from résumé context.
  • Agentic: scheduled collection, retrieval of the relevant CV context, and placement into a review queue.
  • Not autonomous: no auto-apply, no auto-send, no irreversible decision.
  • Provenance to ask for in a code review: which source was used, when the draft was created, and what the human changed.

Security

  • Mailbox send is outside the agent’s permissions.
  • The public demo is read-only so visitors cannot trigger applications.
  • Personal application data should be reviewed, retained, or deleted by the operator — ask for that policy in a code walkthrough.

Monitoring

  • Scheduled jobs are the heartbeat: if 20:00 or 15:00 does not run, the queue goes stale.
  • The public surface is a read-only shortlist, separate from the private mailbox routine.

Limits

  • This is a personal operating system for a job search, not a multi-tenant product.
  • Draft quality still depends on the source posting and the résumé context.
  • Automated test files are in the private source. Public proof is the read-only demo, the schedule, and the send gate.
